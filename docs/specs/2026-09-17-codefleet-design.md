# CodeFleet 설계 명세

- 상태: 검토 초안
- 작성일: 2026-09-17
- 저장소: `wrallee/codefleet`
- 라이선스: MIT

## 목적

CodeFleet은 여러 Git 저장소의 최신 코드 근거를 AI 에이전트에 제공한다.
각 저장소의 원격 기본 브랜치를 추적하고 CodeGraph 색인을 만든 뒤,
원격 MCP 서버를 통해 탐색 결과를 제공한다.

CodeFleet은 독립형 서비스다. 저장소 등록, Git 접근, 동기화 일정, 색인,
관리 기능, 저장 공간을 자체적으로 관리한다.

## 목표

- 하나의 서비스에서 약 10개 저장소를 관리한다.
- 얕은 체크아웃으로 원격 기본 브랜치를 추적한다.
- 관리자가 저장소를 등록, 수정, 동기화, 비활성화, 삭제할 수 있게 한다.
- 색인 동기화 중에도 코드 탐색을 계속 제공한다.
- 모든 탐색 결과에 체크아웃 커밋, 색인 커밋, 최신 상태를 포함한다.
- 에이전트가 MCP를 통해 저장소나 색인 상태를 변경하지 못하게 한다.
- 하나의 영구 `/data` 볼륨을 사용하는 단일 Docker 서비스로 실행한다.

## 제외 범위

- 여러 저장소를 하나의 CodeGraph 색인으로 합치기
- 에이전트의 질문에 맞는 저장소를 자동으로 선택하기
- Kubernetes 배포 파일 또는 다중 인스턴스 조정
- 사용자 계정, 세션, OAuth 또는 대규모 관리용 프런트엔드
- 전체 동기화 이력 보관
- 요청으로 임의의 파일 시스템 경로나 셸 명령을 받기

## 구조

```text
AI 에이전트
    |
    | Streamable HTTP MCP
    v
CodeFleet
    |- codefleet_repositories
    |- codefleet_explore
    |- 관리용 HTTP API와 단일 페이지 관리 화면
    |- 저장소 스케줄러와 동기화 대기열
    |- SQLite 레지스트리
    `- CodeGraph CLI
          |
          v
       저장소별 .codegraph 색인을 포함한 얕은 Git 체크아웃
```

CodeFleet은 하나의 Node.js·TypeScript 프로세스로 실행한다. 공식 MCP
TypeScript SDK를 사용하고 `child_process.spawn`으로 CodeGraph CLI 1.6.0을
호출한다. 셸은 사용하지 않으며 호출자가 전달한 명령을 해석하지 않는다.

첫 버전은 가장 작은 연동 범위로 CodeGraph의 기존 `explore` 동작을 보존하기
위해 CLI를 사용한다. 프로세스 시작 비용이나 질의 처리량 문제가 실제로
측정된 경우에만 CodeGraph Node API 전환을 검토한다. 첫 버전에서 두 경로를
동시에 구현하지 않는다.

## MCP 계약

도구 이름은 CodeGraph의 `product_action` 규칙을 따른다.

### `codefleet_repositories`

에이전트가 탐색할 수 있는 저장소 목록을 반환한다. 각 항목은 다음 필드를
포함한다.

- `repository`
- `display_name`
- `description`
- `branch`
- `state`
- `checkout_commit`
- `indexed_commit`
- `indexed_at`
- 현재 구현으로 확정할 수 있는지 나타내는 `authoritative`

에이전트가 저장소 식별자를 모를 때 이 도구를 호출한다. 비활성화 중이거나
삭제 중인 저장소는 탐색 대상에 포함하지 않는다.

### `codefleet_explore`

입력:

```json
{
  "repository": "orders",
  "query": "Which event types are currently supported?",
  "max_files": 8
}
```

`repository`와 `query`는 필수다. `max_files`에는 제한된 기본값과 최댓값을
둔다. 서비스는 저장소 식별자를 등록된 체크아웃에 연결하며 파일 시스템
경로를 직접 받지 않는다.

출력은 다음 내용을 포함한다.

- 저장소 식별자와 브랜치
- 저장소 상태
- 체크아웃 커밋
- 색인 커밋과 색인 시각
- `authoritative`
- 최신성 경고를 포함한 수정하지 않은 CodeGraph 탐색 결과

저장소 상태가 `ready`이고 체크아웃 커밋과 색인 커밋이 일치할 때만
`authoritative`가 `true`다. 동기화 중이거나 동기화에 실패한 뒤에도 탐색은
계속 제공하지만 `authoritative`는 `false`로 설정한다. 도구 설명에는
확정할 수 없는 결과를 현재 동작으로 단정하지 말라고 명시한다.

동기화, 등록, 삭제 기능은 MCP 도구로 제공하지 않는다.

## HTTP 엔드포인트

서비스는 다음 엔드포인트를 제공한다.

- `POST /mcp`: Streamable HTTP MCP 엔드포인트
- `GET /healthz`: 프로세스 생존 확인
- `GET /readyz`: 데이터베이스와 데이터 디렉터리 준비 상태 확인
- `GET /admin`: 관리용 HTML 페이지
- `/api/repositories`: 인증이 필요한 저장소 관리 API

관리 API는 목록 조회, 등록, 수정, 활성화, 비활성화, 수동 동기화, 삭제를
지원한다. 관리 화면은 서버가 제공하는 하나의 HTML 페이지와 기본 CSS,
JavaScript로 구성한다. 별도 빌드나 프런트엔드 프레임워크는 사용하지 않는다.

## 인증

CodeFleet은 서로 다른 Bearer 토큰 두 개를 사용한다.

- MCP 접근용 토큰
- 관리 API 접근용 토큰

토큰은 환경 변수로 받고 SQLite에는 저장하지 않는다. 관리 페이지는 토큰을
입력받아 브라우저 세션 저장소에 보관하며 API 요청의 `Authorization` 헤더에
담는다. 상태 확인 엔드포인트에는 인증을 요구하지 않는다.

Git 인증 정보도 CodeFleet 외부에서 제공한다. 운영자는 컨테이너에 SSH 키,
SSH 에이전트 또는 Git 자격 증명 도우미를 제공한다. CodeFleet은 Git 인증
정보를 SQLite나 복제 URL에 기록하지 않는다.

등록하는 복제 URL은 허용된 Git 호스트만 사용할 수 있다. 기본 허용 호스트는
`github.com`이다. 운영자는 설정으로 허용 목록을 바꿀 수 있다.

## 레지스트리와 상태

CodeFleet은 `/data/codefleet.db`에 별도 SQLite 데이터베이스를 사용한다.
CodeGraph 데이터베이스에는 애플리케이션 메타데이터를 기록하지 않는다.

저장소 레코드는 다음 정보를 포함한다.

- 식별자, 표시 이름, 설명
- 복제 URL과 확인된 기본 브랜치
- 선택 사항인 5필드 동기화 cron 표현식
- 활성화 여부와 현재 상태
- 체크아웃 커밋과 색인 커밋
- 마지막 색인 시각과 마지막 오류
- 생성 시각과 수정 시각

저장소 상태는 다음과 같다.

- `pending`: 등록됐지만 아직 색인을 만들지 않음
- `syncing`: 복제 또는 증분 동기화 진행 중
- `ready`: 체크아웃과 색인이 일치함
- `degraded`: 마지막 동기화 실패
- `disabled`: 일정 실행과 탐색이 비활성화됨
- `deleting`: 삭제 진행 중이거나 재시도 대기 중

스키마 변경은 SQLite의 `user_version`과 작은 순방향 마이그레이션으로 처리한다.
첫 버전은 현재 상태만 저장하고 작업 이력은 컨테이너 로그에 남긴다.

## 파일 시스템 구조

```text
/data/
  codefleet.db
  repositories/
    orders/
      .git/
      .codegraph/
      ...작업 트리...
  .trash/
```

각 저장소는 체크아웃과 `.codegraph` SQLite 데이터베이스를 함께 가진다.
현재 CodeGraph는 사용자 지정 색인 경로를 지원하지 않으므로 색인은 프로젝트
루트에 둔다. 색인은 파생 데이터이며 다른 Git 저장소에 커밋하지 않는다.

`/data` 볼륨은 SQLite WAL 파일 잠금을 안정적으로 지원하는 파일 시스템을
사용해야 한다. 이를 보장하지 못하는 네트워크 파일 시스템은 지원하지 않는다.

## 등록과 최초 색인

관리자는 고정 식별자, 설명, 복제 URL, 선택 사항인 동기화 일정을 입력한다.
CodeFleet은 `git ls-remote --symref`로 원격 기본 브랜치를 확인해 저장한다.
식별자를 검증한 뒤 `/data/repositories`의 바로 아래 디렉터리 이름으로 사용한다.
호출자는 경로를 직접 지정할 수 없다. 인증 정보나 URL 사용자 정보가 포함된
복제 URL은 거부한다.

최초 색인은 다음 순서로 실행한다.

1. `git clone --depth=1 --single-branch --no-tags --branch <branch>`
2. `codegraph init --yes <repository-path>`
3. `codegraph status <repository-path>`
4. 모든 단계가 성공한 뒤에만 체크아웃 커밋과 색인 커밋 기록

큰 저장소의 최초 색인이 끝나기 전에 등록 요청을 반환한다. 준비될 때까지
저장소 상태는 `pending` 또는 `syncing`이다.

## 증분 동기화

수동 동기화와 예약 동기화는 같은 대기열을 사용한다. 같은 저장소에 대한
반복 요청은 하나의 대기 작업으로 합친다. 첫 버전은 CPU, 메모리, 디스크
사용량을 제한하기 위해 동기화 쓰기 작업을 한 번에 하나만 실행한다.

증분 동기화는 다음 순서로 실행한다.

1. 마지막으로 성공한 색인 커밋 기록
2. 저장소 상태를 `syncing`으로 변경
3. 현재 원격 기본 브랜치 확인
4. 태그 없이 해당 브랜치만 깊이 1로 가져오기
5. 전용 체크아웃을 가져온 커밋으로 이동
6. `codegraph sync <repository-path>` 실행
7. CodeGraph 상태 확인
8. 저장된 브랜치, `indexed_commit`, `indexed_at`을 갱신하고 상태를 `ready`로 변경

동기화 쓰기 작업만 직렬화한다. 동기화가 CodeGraph 데이터베이스에 쓰는 동안에도
탐색은 차단하지 않는다. CodeGraph가 SQLite WAL을 사용하므로 쓰기 작업이
커밋하는 동안 읽기 작업을 계속할 수 있다.

체크아웃 파일과 색인이 다르면 CodeGraph의 디스크 변경 감지와 최신성 경고를
응답에 그대로 남긴다. CodeFleet도 두 커밋, `syncing` 상태,
`authoritative: false`를 함께 반환한다. 동기화 실패 시 상태는 `degraded`가 되고
마지막으로 성공한 색인 커밋을 유지한다. 탐색도 확정 불가 표시와 함께 계속 제공한다.

스케줄러는 시작할 때 SQLite의 cron 표현식을 불러온다. 수동 작업과 예약 작업은
같은 동기화 구현을 사용한다.

## 삭제

삭제는 관리되지 않는 디렉터리를 남기지 않고 저장소 레코드, 체크아웃, Git
메타데이터, CodeGraph 색인을 제거한다.

1. 레코드 상태를 `deleting`으로 변경하고 일정을 중지한다.
2. 해당 저장소의 새 탐색과 동기화 요청을 거부한다.
3. 해당 저장소를 사용 중인 추적된 자식 프로세스가 정상 제한 시간 안에 끝나도록 기다린다.
4. 실제 경로가 설정된 저장소 루트의 바로 아래 디렉터리인지, 심볼릭 링크나 루트 자체가 아닌지 확인한다.
5. 같은 파일 시스템의 `/data/.trash`로 디렉터리를 원자적으로 이동한다.
6. 이동한 디렉터리 트리를 삭제한다.
7. 파일 시스템 삭제에 성공한 뒤에만 SQLite 레코드를 삭제한다.

삭제 실패 시 레코드는 오류 정보와 함께 `deleting` 상태로 남아 재시도할 수 있다.
CodeFleet은 시작할 때 기록된 휴지통 항목의 삭제를 재개한다. 이 순서로 처리하면
레지스트리가 모르는 디렉터리가 생기지 않는다. 알 수 없는 디렉터리는 관리자에게
알리며 자동으로 삭제하지 않는다.

## 동시성과 프로세스 안전

- 같은 저장소의 CodeGraph 쓰기 작업은 겹치지 않는다.
- 첫 버전의 전체 동기화 동시 실행 수는 1이다.
- 탐색 자식 프로세스 수와 출력 크기를 제한한다.
- 모든 자식 프로세스에 제한 시간을 두고 인수를 배열로 전달한다.
- 서비스 종료 시 새 작업을 받지 않고 진행 중인 작업을 제한 시간 동안 기다린 뒤 남은 자식 프로세스를 종료한다.
- 저장소 삭제 전에 추적 중인 작업이 끝날 때까지 기다린다.

서비스는 CodeGraph의 경고와 오류를 모두 보존한다. 명령이 성공했다는 이유만으로
결과가 최신이라고 판단하지 않는다.

## 오류 계약

관리 API와 MCP 오류는 안정적인 기계 판독용 코드, 사람이 읽는 메시지,
저장소 상태, 재시도 가능 여부를 포함한다. 첫 버전은 다음 오류를 다룬다.

- 저장소를 찾을 수 없음
- 저장소가 비활성화 또는 삭제 중임
- 잘못된 복제 URL, 일정, 식별자 또는 확인할 수 없는 기본 브랜치
- 인증 실패
- 동기화 또는 탐색 제한 시간 초과
- Git 또는 CodeGraph 명령 실패
- 출력 제한 초과
- 삭제 실패

로그에는 요청 또는 작업 식별자, 저장소 식별자, 명령 이름, 종료 상태, 실행
시간을 남긴다. Bearer 토큰, Git 인증 정보, 자연어 질의 전문은 기록하지 않는다.

## 검증

프로젝트는 다음 세 단계로 검증한다.

1. MCP 계약 테스트에서 `codefleet_repositories`, `codefleet_explore`, 인증, 필드 이름, 확정 가능 상태를 확인한다.
2. 임시 Git 저장소와 통제된 자식 프로세스를 사용하는 저장소 생명주기 테스트로 얕은 복제, 예약·수동 동기화, 동시 탐색, 실패, 삭제, 재시작 정리를 확인한다.
3. 작은 예제 저장소를 초기화하는 실제 CodeGraph 통합 테스트에서 예상한 심볼과 소스 근거가 반환되는지 확인한다.

지속적 통합은 타입 검사, 테스트, Docker 이미지 빌드를 실행한다. 비공개 인증
정보나 실제 GitHub 저장소는 필요하지 않다.

## 최초 프로젝트 구조

```text
src/
  server.ts                  # 프로세스 시작과 의존성 연결
  admin/
    routes.ts                # 관리 화면과 관리 API
  codegraph/
    client.ts                # CodeGraph 자식 프로세스 실행
  mcp/
    server.ts                # MCP 도구와 전송 계층
  registry/
    database.ts              # SQLite 연결과 마이그레이션
  repositories/
    service.ts               # 저장소 생명주기와 동기화 조정
test/
Dockerfile
package.json
tsconfig.json
README.md
LICENSE
```

파일에 두 번째 독립 책임이 생긴 경우에만 구조를 더 나눈다. 첫 버전에서는
프레임워크 계층, 공급자 인터페이스, 추측성 어댑터를 추가하지 않는다.

## 보류 항목

- CodeGraph Node API 최적화
- 여러 CodeFleet 인스턴스 실행
- PostgreSQL 레지스트리
- Kubernetes 배포 파일
- 저장소 자동 선택
- 여러 저장소를 합친 그래프
- 동기화 이력 화면
- 사용자 계정과 OAuth
- 외부 색인 백업 또는 스냅숏

이 항목은 필요가 실제로 측정되거나 새로운 배포 요구가 생겼을 때 검토한다.
